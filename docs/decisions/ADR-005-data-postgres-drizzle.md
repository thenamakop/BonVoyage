# ADR-005: Data with PostgreSQL and Drizzle

Status: Accepted · Date: 2026-10-10 · Supersedes: none

## Context

Requirement R11 asks for relational persistence with referential integrity (`docs/baseline/BonVoyage_SRS_v1.1.md` section 3.4). The catalogue holds fewer than 500 destinations, so the data set is small and geospatial extensions are not justified.

## Decision

Use PostgreSQL with Drizzle ORM (the latest stable release, never a beta) and versioned SQL migrations generated by drizzle-kit, with snake_case column casing. Do not use PostGIS; haversine distance is enough. Run Docker Postgres locally and Neon when deployed.

## Consequences

- Easier: migrations are plain SQL files that are reviewed and committed.
- Easier: the same engine locally and in production keeps behaviour identical.
- Harder: a migration already on `master` is never edited, so every fix is a new migration.
- Harder: no spatial queries, so any future geospatial feature needs a new decision.
