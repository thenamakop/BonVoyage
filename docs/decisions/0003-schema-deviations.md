# 0003: Schema deviations from the baseline documents

Status: Accepted · Date: 2026-10-12 · Supersedes: none

## Context

S0-5 turns SRS v1.1 Table 10 plus RUNBOOK Phase 6's data stores into one reviewed migration. A few names and structures differ from the older documents; each is recorded here so the difference is a decision, not drift.

## Decision

- **`trip_package` instead of `package`.** `package` is a reserved word in strict-mode TypeScript, so the Drizzle table and its `package_id` foreign keys use `trip_package`.
- **`user_profile` instead of columns on Better Auth's `user` table.** Better Auth owns `user`, `session`, `account` and `verification`; that file is regenerated by its CLI and never hand-edited. Everything the app needs about a user (today: the home hub) lives in `user_profile`, keyed by `user_id` with a cascade.
- **`trip.origin_hub_id` instead of `origin_name`, `origin_lat`, `origin_lng`.** Without a geocoding key (ADR-007) a free-text origin cannot be resolved reliably, so trips start from a curated hub; SRS Table 5's "resolves to valid coordinates" is met by the hub's curated coordinates.
- **Link invitations carry `active` / `revoked` statuses.** Email invitations wait for the reminders work (C4); links are the mechanism for 10 November.
- **`trip_transition` is a new audit table.** It records (transition_id, event, from_status, to_status, actor, created_at) and is written by `transitionTrip` in S0-6.
- **`cost_rule` is a table** keyed by rule name so fuel and mileage assumptions stay data, not code.
- **`destination.active`** lets an administrator deactivate a row rather than delete it (deleting would break `restrict` foreign keys from recommendation items and packages).
- **`fare_fallback` keeps its RUNBOOK name** although curated data is the primary source; the table stores both curated and fallback fare rows.

## Consequences

- Easier: the four auth tables stay in step with the Better Auth version by re-running `npx auth generate` instead of hand-maintenance.
- Easier: every trip row points at a real, geocoded hub; no free-text geocoding is needed.
- Harder: code and queries must use `trip_package`, `user_profile` and `origin_hub_id` names; documents written earlier still say `package`, `origin_name` and friends.
